# 101-runtime-launch-orchestration 模块规格

> Module: 101-runtime-launch-orchestration（应用入口编排）
> Status: Implemented
> Last Updated: 2026-08-14

## 1. Module Overview

### 1.1 Purpose — 为什么存在这个模块

本模块是桌面应用的进程级入口编排器，负责从进程启动到优雅退出的全生命周期协调。它本身不实现任何桌面能力，而是按既定顺序**装配**其它模块（宿主启动、窗口、托盘、通知、生命周期安全），保证应用在正确的时机、以正确的状态启动、驻留与退出。

### 1.2 Problems Solved — 解决的问题

- **多实例竞争**：若允许多实例，会同时挂起多个宿主与 webserver，各自绑定不同端口，托盘图标与通知来源混乱。通过单实例锁保证同一时刻只有一个应用实例，重复启动时聚焦已有窗口。
- **启动顺序依赖**：宿主必须在窗口加载前就绪，否则渲染进程会加载到未就绪的 localhost 页面。通过编排固定的启动序列解决。
- **关窗退出**：桌面应用要求「关窗即退出」，关闭窗口时彻底退出并释放宿主资源。通过「关窗 → window-all-closed → app.quit」单一路径解决。
- **安装器短生命周期进程**：Windows 安装器（Squirrel）在安装/卸载时会以特殊参数短暂拉起本进程，须在最早期识别并静默退出，避免弹出无意义窗口。
- **原生通知前置条件**：Windows 原生通知依赖应用标识，须在就绪后尽早设置。

### 1.3 Scope — 范围

**包含**：

- 单实例锁与第二实例聚焦
- 安装器（Squirrel.Windows）短生命周期处理
- 启动前安全准备（系统证书、loopback 代理豁免、崩溃兜底）
- 宿主启动编排与窗口创建顺序
- 托盘与通知的装配时机
- 生命周期事件处理（关窗退出、优雅退出）

**不包含**（由其它模块承担）：

- 宿主的实际启动逻辑（`host.ts`）
- 窗口创建、无边框、安全加固细节（`windows.ts`）
- 托盘菜单与图标（`tray.ts`）
- 通知的事件订阅与文案（`notifications.ts`）
- 证书/代理/崩溃兜底的具体实现（`lifecycle.ts`）

## 2. User Stories

- 作为用户，当我重复启动应用时，已有实例的窗口应被唤起并聚焦，而不是再开一个新实例。
- 作为用户，我希望应用启动后窗口能正常显示宿主界面（宿主就绪前不出现空白/加载竞争）。
- 作为用户，我希望关闭窗口后应用彻底退出并释放后端服务，不留残留进程。
- 作为用户，当我从托盘选择「退出」时，应用应彻底退出并优雅释放后台宿主资源，不留残留进程。
- 作为用户，我希望在 Windows 上安装/卸载应用时，安装器临时进程不会弹出应用窗口。

## 3. Functional Requirements

### 3.1 单实例

- FR-101-001：系统 MUST 在进程启动最早阶段申请单实例锁；获取失败时 MUST 立即退出进程。
- FR-101-002：系统 MUST 在第二实例启动时，唤醒并聚焦已有实例的主窗口（最小化则先还原）。

### 3.2 安装器短生命周期处理

- FR-101-003：系统 MUST 在入口最前识别安装器（Squirrel.Windows）触发的安装/卸载事件，并立即退出进程，不进入正常启动流程。

### 3.3 启动前安全准备

- FR-101-004：系统 MUST 在窗口创建之前完成启动前安全准备（系统证书合并、loopback 代理豁免、崩溃兜底注册）。

### 3.4 启动编排

- FR-101-005：系统 MUST 在应用就绪后、创建窗口前，设置 Windows 原生通知所需的 AppUserModelID。
- FR-101-006：系统 MUST 在创建窗口前注册窗口控制 IPC 处理器。
- FR-101-007：系统 MUST 先启动宿主并取得其句柄，再据此创建主窗口。
- FR-101-008：系统 MUST 在宿主不可用（未接入/启动失败）时加载兜底页，不阻塞应用启动。
- FR-101-009：系统 MUST 仅在宿主可用（可提供宿主上下文）时才装配托盘与通知。
- FR-101-010：系统 MUST 在应用被重新激活且无任何窗口时，重新创建主窗口。

### 3.5 生命周期

- FR-101-011：系统 MUST 在全部窗口关闭后退出进程（关窗即退出，触发 before-quit 优雅关闭 dsh Host）。
- FR-101-012：系统 MUST 在退出前执行优雅关闭：关闭宿主、销毁托盘。

## 4. Key Entities

| 实体 | 描述 | 关键属性 |
|---|---|---|
| 主窗口句柄 | 当前主窗口的引用 | 可空；用于第二实例聚焦与激活重建 |
| 宿主句柄 | 宿主启动返回的句柄 | 上下文、关闭函数、端口、URL；可空 |
| AppUserModelID | Windows 原生通知的应用标识 | 固定字符串 |

## 5. Acceptance Scenarios

### Scenario: 重复启动聚焦已有窗口

- Given 应用已有一个运行实例且窗口最小化
- When 用户再次启动应用
- Then 第二实例不创建新窗口，已有实例还原并聚焦其窗口

### Scenario: 安装器临时进程静默退出

- Given 进程以安装器（Squirrel.Windows）安装/卸载参数启动
- When 入口代码运行
- Then 进程立即退出，不创建窗口、不启动宿主

### Scenario: 正常启动顺序

- Given 无其它实例运行，且宿主启动成功
- When 应用完成安全准备并进入就绪状态
- Then 先注册窗口控制 IPC，再启动宿主，再创建加载宿主地址的主窗口，最后装配托盘与通知

### Scenario: 宿主不可用时的兜底

- Given 宿主启动未接入（返回空句柄）
- When 应用进入就绪状态
- Then 仍创建主窗口并加载兜底页，不装配托盘与通知，进程不崩溃

### Scenario: 关窗退出

- Given 应用运行中，用户关闭主窗口
- When 全部窗口关闭
- Then 应用调用宿主关闭、销毁托盘并退出进程（关窗即退出）

## 6. Non-Functional Requirements

- **可靠性**：崩溃兜底保证进程异常时至少记录，不静默崩溃；启动序列任一环节不可用时须降级而非崩溃（如宿主不可用走兜底页）。
- **性能**：安装器识别与单实例锁判断须在进程启动最早阶段完成，避免无谓初始化。
- **可维护性**：编排逻辑线性、可读，各职责委托给独立模块，入口自身保持薄。
- **可移植性**：支持 Windows + Linux；macOS 相关行为（如激活重建窗口）沿用平台默认语义。

## 7. Assumptions & Constraints

- 宿主在 MVP 阶段运行于主进程内（进程内 Host），入口直接持有其句柄；未来迁移到子进程时渲染进程无感知。
- 脚手架阶段宿主尚未接入，启动函数返回空句柄，入口据此走兜底页路径。
- 关窗退出策略：关窗即放行关闭，入口的 `window-all-closed` 调用 `app.quit()`，经 `before-quit` 优雅关闭 dsh Host 后退出；托盘「退出」为等效退出通道。

## 8. Dependencies

- **上游**：宿主启动模块、窗口模块、托盘模块、通知模块、生命周期安全模块。
- **下游**：渲染进程（通过窗口加载地址间接）、打包产物（安装器依赖本模块的短生命周期处理）。
- **外部**：Squirrel.Windows 安装器（触发短生命周期进程）、操作系统（单实例锁、原生通知、应用标识）。
