# 窗口管理 功能规格

> Module: 103-window-shell
> Status: Implemented
> Last Updated: 2026-08-14

## 1. 模块概述

### 1.1 目的（Why this module exists）

负责桌面应用主窗口的创建、加载与安全加固：

1. **创建无边框主窗口**，并在 Windows 平台提供自绘标题栏，与 dsh Web UI 视觉一体；
2. **同源加载** dsh Host 提供的 localhost 界面（宿主未就绪时降级到兜底页 / 开发服务器）；
3. **安全加固**渲染进程——渲染进程加载的是宿主提供的本地内容，须按不可信内容对待；
4. **窗口控制**（最小化 / 最大化 / 关闭）经薄 IPC 暴露给渲染层（`window.dsh`）；
5. **关窗退出**——放行窗口关闭，由入口模块触发应用退出（关窗即退出）。

### 1.2 解决的问题（What pain points it addresses）

- **安全风险**：渲染进程加载 localhost 上的 dsh Web UI，若含 XSS 或恶意内容，未加固的渲染进程可被提权到 Node 环境。本模块通过进程隔离、导航加固、权限白名单将攻击面降到最低。
- **无边框窗口的控制缺失**：去掉系统边框后，最小化/最大化/关闭失去系统入口，需自绘标题栏并暴露窗口控制接口给渲染层。
- **视觉割裂**：有边框窗口与 dsh Web UI 的视觉风格不统一；无边框 + 自绘标题栏实现「界面一体」。
- **白屏闪烁**：直接显示未加载完成的窗口会导致白屏；「就绪后再显示」提升体验。
- **误退出**：用户点关闭常期望「最小化到托盘后台运行」而非退出，需区分「关窗」与「真正退出」。

### 1.3 范围（Scope）

**包含**：

- 主窗口创建（尺寸、无边框、标题栏样式、预加载脚本、渲染进程隔离配置）；
- 加载逻辑（宿主 localhost / 开发服务器 / 兜底页三级降级）；
- 导航加固与权限白名单；
- 窗口控制薄 IPC 的注册（min/max/close/is-maximized）；
- 关窗即退出（放行 close，由入口模块触发应用退出）。

**不包含**：

- 宿主启动与端口（见 `115-host`，本模块只**消费**其 url）；
- 系统托盘的创建与菜单（见 `tray` 模块）；
- 原生通知（见 `notifications` 模块）；
- 剪贴板图片的实际粘贴处理（走 dsh 图片附件路径，本模块仅通过权限白名单**放行**剪贴板写入）。

## 2. 用户故事

- 作为用户，我希望应用拥有无边框窗口与自绘标题栏，使 dsh Web UI 呈现为原生桌面应用的观感。
- 作为用户，我希望通过界面上的标题栏按钮（最小化 / 最大化 / 关闭）控制窗口。
- 作为用户，我希望关闭窗口后应用彻底退出并释放后端服务，不留残留进程。
- 作为用户，我希望在应用内粘贴剪贴板图片（走 dsh 图片附件路径）时不被安全策略拦截。
- 作为用户，我希望应用能发出系统通知（权限被正确放行）。
- 作为用户，我希望点击界面中的外部链接时，用系统默认浏览器打开，而不是在应用窗口内跳转。

## 3. 功能需求

### 3.1 窗口创建与标题栏

- FR-103-001：系统 MUST 创建无边框主窗口，并在 Windows 平台提供自绘标题栏（透明背景，让渲染层自绘）。
- FR-103-002：系统 SHOULD 为非 Windows 平台提供无边框/隐藏标题栏的等价处理；Linux 因不支持 titleBarOverlay/titleBarStyle，当前保留系统默认边框（平台差异，自绘标题栏需配合前端注入，后续实现）。

### 3.2 加载与降级

- FR-103-003：系统 MUST 在宿主就绪时，让窗口同源加载宿主提供的 localhost 界面。
- FR-103-004：系统 MUST 在宿主未就绪时降级加载——优先开发服务器地址，否则加载本地兜底页。

### 3.3 渲染进程隔离

- FR-103-005：系统 MUST 隔离渲染进程：启用沙箱、启用上下文隔离、禁用 Node 集成。
- FR-103-006：系统 MUST 通过预加载脚本仅暴露白名单化的窗口控制接口，不向渲染进程暴露 Node 能力。

### 3.4 导航加固

- FR-103-007：系统 MUST 仅允许受信来源（回环 localhost / 开发服务器）在应用窗口内原地导航；其它外部地址 MUST 交由系统默认浏览器打开。
- FR-103-008：系统 MUST 拒绝渲染层通过新窗口打开任意地址，外部地址交系统浏览器。

### 3.5 权限白名单

- FR-103-009：系统 MUST 仅放行白名单权限（安全剪贴板写入 + 通知），且同时满足「受信来源」与「对应窗口」两个条件。

### 3.6 窗口控制

- FR-103-010：系统 MUST 提供窗口最小化、最大化/还原、关闭、最大化状态查询的薄 IPC 接口，供渲染层调用。

### 3.7 关窗退出

- FR-103-011：系统 MUST 放行窗口关闭事件（不拦截），使窗口关闭后由入口模块触发应用退出（关窗即退出，见 101-runtime-launch-orchestration FR-101-011）。

### 3.8 显示与错误

- FR-103-013：系统 MUST 在窗口内容就绪后再显示窗口，避免白屏。
- FR-103-014：系统 MUST 记录页面加载失败（错误码、描述、失败 URL），便于诊断。

## 4. 关键实体

| 实体 | 说明 | 关键属性 |
|------|------|----------|
| 主窗口（BrowserWindow） | 桌面应用唯一主窗口 | 尺寸（1200×800，最小 800×600）、无边框、标题栏样式、渲染隔离配置、预加载脚本 |
| 权限白名单（RENDERER_PERMISSIONS） | 允许渲染层申请的权限集合 | `clipboard-sanitized-write`、`notifications` |
| 受信来源判定 | 判断 URL 是否允许原地导航/申请权限 | 回环 http（127.0.0.1 / localhost）或开发服务器前缀 |

## 5. 验收场景

### 场景：无边框 + 自绘标题栏（Windows）

- Given 运行于 Windows 平台
- When 创建主窗口
- Then 窗口无系统边框，使用自绘标题栏（透明背景、自适应明暗的按钮颜色、固定标题栏高度）

### 场景：同源加载宿主界面

- Given 宿主已就绪并返回 localhost URL
- When 创建主窗口
- Then 窗口加载 `http://127.0.0.1:<port>/`，渲染进程与宿主同源

### 场景：宿主未就绪降级

- Given 宿主未接入（返回 null），且无开发服务器
- When 创建主窗口
- Then 窗口加载本地兜底页，不崩溃

### 场景：外部链接走系统浏览器

- Given 界面内出现指向外部站点的链接
- When 用户点击该链接（或页面尝试导航到外部地址）
- Then 应用窗口不跳转，系统默认浏览器打开该地址

### 场景：关闭窗口退出应用

- Given 应用处于运行状态
- When 用户关闭窗口
- Then 窗口关闭，应用退出（关窗即退出，触发优雅关闭）

### 场景：真正退出放行关闭

- Given 用户通过托盘「退出」触发应用退出流程
- When 应用退出，关闭窗口
- Then 窗口关闭事件被放行，应用正常退出

### 场景：窗口控制

- Given 窗口已创建
- When 渲染层调用最小化 / 最大化 / 关闭 / 状态查询
- Then 对应窗口操作被执行，状态查询返回真实状态

## 6. 非功能需求

- **性能**：窗口创建后不立即显示，待内容就绪再显示，避免白屏；桌面壳自身开销最小化。
- **可维护性**：安全配置、权限白名单、受信来源判定集中在本模块，便于审计与调整。
- **安全性**：渲染进程加载的是宿主提供的本地内容，须按不可信内容对待（沙箱 + 隔离 + 导航加固 + 权限白名单）。
- **可移植性**：标题栏处理区分 Windows / 非 Windows 平台；后续 macOS 可平滑接入。

## 7. 假设与约束

- **假设**：受信来源仅限回环 http（127.0.0.1 / localhost）与开发服务器；不信任任何其它 http/https 地址在窗口内原地导航。
- **假设**：预加载脚本对该窗口加载的**所有**页面（含 loadURL 到 localhost 的 dsh Web UI）生效，即 dsh UI 可经 `window.dsh` 控制无边框窗口。
- **约束**：权限白名单固定为「安全剪贴板写入 + 通知」，不开放其它权限；如需新权限须显式加入白名单并重新评估风险。
- **约束**：关窗即退出——窗口关闭后由入口模块的 `window-all-closed` 触发应用退出（见 101-runtime-launch-orchestration FR-101-011）。

## 8. 依赖

**上游（被本模块消费）**：

- `115-host`：提供宿主 localhost URL（宿主为 null 时本模块走降级路径）。
- 生命周期模块：关窗即退出由入口模块的 `window-all-closed` 触发。

**下游（消费本模块）**：

- `index`（启动编排）：调用 `createMainWindow(url)`、`registerWindowIpcHandlers()`。
- `preload`：通过 `contextBridge` 暴露 `window.dsh`，调用本模块注册的窗口控制 IPC。
- `tray`：托盘「显示主窗口」依赖本模块创建的窗口实例。
