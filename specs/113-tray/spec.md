# 系统托盘规格

> Module: 113-tray
> Status: Implemented（脚手架阶段）
> Last Updated: 2026-08-14

## 1. 模块概述

### 1.1 目的 — 为什么存在这个模块

让 deepseek-harness 桌面应用提供系统托盘入口：托盘图标标识应用身份，用户可从托盘唤回最小化的主窗口或彻底退出。

### 1.2 解决的问题 — 解决哪些痛点

- 没有常驻入口时，用户难以快速唤回最小化的窗口或退出应用。
- 需要一个明确的「退出」通道（与关窗退出等效）。

### 1.3 范围 — 包含与不包含

**包含**：
- 系统托盘图标 + 右键上下文菜单（显示主窗口 / 退出）。
- 点击托盘图标唤起主窗口。
- 托盘资源的创建与销毁。

**不包含**：
- 托盘图标为「真实图标」——当前为占位空图标，替换为 `resources/` 下的真实图标是后续 TODO。
- 全局快捷键唤起、开机自启、多窗口（整体项目暂缓项）。
- 「关窗即退出」本身——由窗口模块与入口模块处理，本模块只提供托盘入口与「退出」通道。

## 2. 用户故事

- 作为用户，我希望应用启动后能在系统托盘看到图标。
- 作为用户，我希望点击托盘图标能唤起主窗口，以便随时回到应用。
- 作为用户，我希望通过托盘菜单的「显示主窗口」唤回被最小化/隐藏的主窗口。
- 作为用户，我希望通过托盘菜单的「退出」彻底关闭应用，以便真正结束进程。

## 3. 功能需求

### 3.1 托盘创建

- FR-113-001：系统 MUST 在宿主就绪后创建系统托盘图标。
- FR-113-002：托盘 SHOULD 展示悬浮提示文本（应用名），以标识应用身份。

### 3.2 唤起主窗口

- FR-113-003：托盘菜单 MUST 提供「显示主窗口」操作，用于唤回主窗口。
- FR-113-004：用户点击托盘图标时，系统 MUST 唤起主窗口。
- FR-113-005：唤回主窗口时，若窗口处于最小化状态，系统 MUST 先还原窗口；随后系统 MUST 显示并聚焦窗口。

### 3.3 真正退出

- FR-113-006：托盘菜单 MUST 提供「退出」操作，作为真正退出应用的入口。
- FR-113-007：用户选择「退出」时，系统 MUST 触发应用退出流程（区别于「隐藏到后台」）。

### 3.4 资源生命周期

- FR-113-008：应用退出时，系统 MUST 销毁托盘资源，避免残留。

## 4. 关键实体

| 实体 | 描述 | 关键属性 |
|---|---|---|
| 托盘句柄 | 模块级持有的系统托盘引用，单例 | 存在性（已创建 / 未创建） |
| 主窗口引用 | 托盘操作的目标窗口 | 最小化状态、可见性 |
| 托盘菜单项 | 托盘右键菜单的动作项 | 「显示主窗口」「退出」（分隔线） |

## 5. 验收场景

### 场景：启动后托盘驻留

- Given 应用已启动且宿主已就绪
- When 主窗口创建完成
- Then 系统托盘中出现应用图标，且悬浮提示显示应用名

### 场景：点击托盘图标唤起窗口

- Given 应用在后台运行，主窗口已最小化/隐藏
- When 用户点击托盘图标
- Then 主窗口被还原、显示并聚焦

### 场景：通过菜单显示主窗口

- Given 主窗口处于最小化状态
- When 用户在托盘菜单选择「显示主窗口」
- Then 主窗口被还原、显示并聚焦

### 场景：通过托盘退出应用

- Given 应用在后台运行
- When 用户在托盘菜单选择「退出」
- Then 应用触发退出流程，托盘资源被销毁，进程结束

## 6. 非功能需求

- **可靠性**：托盘单例引用须妥善管理，创建/销毁成对，避免悬挂引用。
- **平台**：Windows + Linux（macOS 后续考虑）。
- **可维护性**：托盘图标当前为占位，后续替换为 `resources/` 真实图标时不应影响其它行为。

## 7. 假设与约束

- **假设**：托盘图标为占位空图标（脚手架阶段），替换为真实图标是已记录的 TODO，不影响托盘菜单与点击行为。
- **约束**：托盘创建依赖「宿主已就绪」（宿主就绪后才创建主窗口，进而创建托盘）。
- **约束**：关窗即退出由窗口模块与入口模块处理，本模块只提供托盘入口与「退出」通道。

## 8. 依赖

- **上游依赖**：宿主集成模块（提供「宿主是否就绪」判定）；窗口模块（提供主窗口引用）。
- **下游依赖**：生命周期编排（启动时创建托盘、退出时销毁托盘）。
