# 005 生命周期与安全 规格说明

> 模块：114-lifecycle-safety（生命周期与安全）
> 状态：Implemented（脚手架阶段已实现）
> 最后更新：2026-08-14

## 1. 模块概述

### 1.1 目的 —— 为什么存在这个模块

本模块负责桌面壳启动前的「安全准备」与运行期的「崩溃兜底」。由于宿主（dsh Host，含 webserver）在 MVP 阶段运行于主进程内，主进程异常即应用级崩溃，因此必须在启动早期做好三件事：

1. 让本机 loopback 地址（宿主 webserver 所绑定的 `127.0.0.1` 等）绕开系统代理，避免本地请求被代理劫持导致功能失效。
2. 将系统级 CA 证书合并进默认信任集，避免企业代理 / 自签证书环境下 Electron 无法完成证书校验。
3. 捕获未处理异常与未处理的 Promise 拒绝并记录，防止进程静默崩溃、无任何痕迹。

### 1.2 解决的问题

- 系统配置了代理时，指向 loopback 的本地宿主请求可能被误走代理，导致同源加载与数据面通信失败。
- 企业代理或自签证书环境下，默认证书集不含系统 CA，导致证书校验失败、应用无法正常联网。
- 宿主在主进程运行时，一次未捕获异常或未处理拒绝即可导致整个应用崩溃，且若静默则无从排查。

### 1.3 范围

**包含**：代理豁免注入、系统 CA 合并、崩溃兜底记录。

**不包含**：宿主进程隔离（utilityProcess 迁移）、日志框架接入（当前用 `console` 占位）、优雅关闭（`shutdown.shutdown()`，位于主进程编排 `src/main/index.ts`，非本模块）。

## 2. 用户故事

- 作为用户，我使用系统代理（含企业代理）时，桌面应用内部对本地宿主的访问不应被代理劫持，界面与数据面通信应正常。
- 作为企业用户，我处于自签证书 / 企业 CA 环境时，应用应能正常校验证书并联网，而非启动即报证书错误。
- 作为开发者/用户，当应用发生崩溃时，我应能在日志中看到异常记录，以便定位问题，而非无任何痕迹地静默退出。

## 3. 功能需求

### 3.1 代理豁免

- FR-114-001：系统 MUST 在宿主启动之前，将 loopback 地址（`127.0.0.1`、`localhost`、`::1`）并入代理豁免列表（大小写两种环境变量键均需处理），使本地宿主请求不被系统代理劫持。
- FR-114-002：系统 MUST 为渲染进程配置 loopback 直连（代理绕过），保证同源加载本地宿主不被代理拦截。

### 3.2 系统证书

- FR-114-003：系统 MUST 在启动时把系统级 CA 证书合并进默认信任集，使企业代理 / 自签证书可被正常校验。
- FR-114-004：系统 MUST 在底层运行时不支持证书合并能力时安全降级——跳过合并而不抛错、不中断启动。

### 3.3 崩溃兜底

- FR-114-005：系统 MUST 捕获未处理异常并记录，防止进程静默崩溃。
- FR-114-006：系统 MUST 捕获未处理的 Promise 拒绝并记录，防止静默失败。
- FR-114-007：系统 MUST 以显式标记区分不同来源的崩溃记录，便于排查。

## 4. 关键实体

| 实体 | 描述 | 关键属性 |
|---|---|---|
| 代理豁免列表 | 需要绕开系统代理的主机集合 | loopback 主机（`127.0.0.1`/`localhost`/`::1`），去重合并 |
| 默认 CA 证书集 | 用于 TLS 证书校验的信任证书集合 | `default` 来源证书 + `system` 来源证书，去重合并 |
| 崩溃记录 | 未处理异常 / 未处理拒绝的日志记录 | 异常对象 / 拒绝原因，来源前缀标记 |

## 5. 验收场景

### 场景：系统代理环境下本地请求不被劫持

- Given 系统配置了代理，且环境变量中已存在部分代理豁免主机
- When 应用启动完成代理豁免注入
- Then loopback 主机被追加进代理豁免列表，且不产生重复项；渲染进程对本地宿主的访问直连、不走代理

### 场景：企业自签证书环境下证书可被校验

- Given 底层运行时支持读取与设置默认证书的能力
- When 应用启动执行证书合并
- Then 默认信任集包含系统 CA 证书，企业代理 / 自签证书可被校验

### 场景：运行时不支持证书合并能力时降级

- Given 底层运行时缺少证书合并相关能力
- When 应用启动执行证书合并
- Then 操作被跳过，不抛异常，启动流程继续

### 场景：发生未处理异常 / 未处理拒绝

- Given 主进程内发生未捕获异常或未处理的 Promise 拒绝
- When 异常 / 拒绝发生
- Then 系统记录该异常 / 拒绝（带来源标记），进程不被静默吞掉错误

## 6. 非功能需求

- **健壮性**：证书合并等能力缺失时降级不中断启动；代理豁免注入需幂等、去重。
- **可维护性**：崩溃兜底记录方式可替换（当前为占位实现，需接入日志框架）。
- **安全性**：仅注入 loopback 代理豁免，不扩大豁免范围至无关主机；证书合并不覆盖已有默认证书（仅并集）。
- **兼容性**：对底层运行时不支持的新增 API 保持兼容（运行时守卫）。

## 7. 假设与约束

- **假设**：底层运行时提供读取「默认 / 系统」CA 证书并设置默认证书的能力（对应 Node 24.4+ 的 `node:tls` API）；不具备时降级跳过。
- **已知代价**：MVP 阶段宿主在主进程运行，主进程异常即应用级崩溃；本模块仅「记录 + 防静默」，不尝试恢复或进程隔离。
- **约束**：崩溃兜底当前使用 `console` 输出占位，尚未接入日志框架。

## 8. 依赖

- **上游**：无（本模块为启动早期被调用的安全准备，无上游模块输入）。
- **下游 / 消费者**：主进程启动编排（`src/main/index.ts`）在应用就绪前调用本模块的三个能力。
- **参考**：opencode desktop 主进程的 NO_PROXY / CA / 崩溃观测模式。
